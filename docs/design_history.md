# 설계 이력 (2025-05-19 ~ 05-30)

팀 Notion에 날짜별로 남긴 RTL 스냅샷을 기준으로 정리했다. 코드가 남아 있는 사실만 적었고, 폐기 이유가 기록되지 않은 항목은 "기록 없음"으로 둔다.

| 날짜 | 스냅샷 | 주요 변화 |
|---|---|---|
| 05-19 | v1 | 단일 CPU 기준으로 x1, x2 계산 어셈블리 시퀀스와 루프(카운터 `lw → addi → sw`, `beq`/`j`) 작성 |
| 05-21 | v2 | ISA 확정: MIPS R/I/J 포맷에 `mul`(funct `100001`), `div`(funct `100011`)를 추가. ALU를 Q15.16 고정소수점으로 변경(`alu_v2`) |
| 05-21 | v2 (폐기) | 외부 shared memory와 DMA 컨트롤러 FSM으로 초기 데이터를 두 코어에 복사하는 구조 검토. 이후 취소선 처리되고 테스트벤치에서 각 코어 data memory를 직접 초기화하는 방식으로 대체 |
| 05-25 | v3 | CPU0, CPU1로 모듈 분리(`_0`, `_1` 접미사), `exchange_if` 인터페이스(방향별 2-word 버퍼 + modport) 도입 |
| 05-25 | v3 수정본 1 | `valid`/`ready` 핸드셰이크와 PC `stall`로 교환 타이밍 보장 시도. 최종본에 채택되지 않음(폐기 이유 기록 없음) |
| 05-25 | v3 수정본 2 | 커스텀 명령 `rec`(opcode `010101`) 추가. 실행 시 상대 코어 버퍼를 data memory[10:11]로 복사 |
| 05-26 | v4 (최종) | 분기 로직 수정. v3는 `jump ? JTA : (zero ? BEQ_Address : BNE_Address)` 구조라 `branch=1`이면 zero 값과 무관하게 항상 BTA로 분기했음 → `(zero && branch) ? BTA : PC+4`로 교체. JTA를 `instruction[25:2]` 기반으로 바꿔 J 필드를 바이트 주소로 해석. 테스트벤치 계층 참조 초기화, 커버그룹과 immediate assertion 추가 |
| 05-27 | v4 memory reset | data/instruction memory를 reset 시 초기화하는 변형. Notion에 "사용하지 말 것"으로 표시 |
| 05-28 | 합성용 변형 | 게이트 레벨 시뮬레이션을 위해 reset 시 메모리·레지스터를 초기화하는 버전. CPU1만 완료 표시, CPU0은 미완 |
| 05-30 | 보고서 제출 | Oasys 합성, P&R, 게이트 레벨 지연 측정 결과 포함 |

이 레포의 `rtl/`은 보고서의 코드 스크린샷과 모듈 단위로 대조해 일치한 **05-26 v4**를 기준으로 한다.

## 교환 방식 결정: 핸드셰이크 → `rec` 명령

| | v3 수정본 1: valid/ready + stall | v4: `rec` 커스텀 명령 |
|---|---|---|
| 동기화 | 하드웨어 핸드셰이크, 미완료 시 PC 정지 | 없음. 두 코어가 같은 길이의 프로그램을 같은 사이클에 실행한다는 lockstep 전제 |
| 추가 로직 | 방향별 valid/ready 4쌍, stall 경로 | opcode 1개, data memory 쓰기 포트에 mux 1개 |
| 교환 지연 | 핸드셰이크 왕복 사이클 | `sw`(버퍼 기록) 2회 + `rec` 1사이클 |
| 한계 | — | 코어 간 명령 수가 달라지면 이전 반복 값을 읽을 수 있음 |

2026년 재검증 TB는 lockstep 전제를 매 사이클 두 코어의 PC 비교로 검사한다(`make check`).
